## 1. 设计目标

舵轮分控板位于主控与执行器之间，负责把主控下发的运动目标转换为
可执行的舵向角和轮向速度，同时保证通信异常时整轮安全停止。

1.0 的核心目标：

1. 通过独立 CAN2 接收主控控制和心跳；
2. 通过 CAN1 与 GM6020、VESC 通信；
3. 把主控二维运动方向转换为舵轮本地舵向和 ERPM；
4. 对舵向目标做速度、加速度平滑；
5. 主控、GM6020 或 VESC 任一异常时整轮失能；
6. 提供 LED 和串口诊断，便于联调和故障定位。

## 2. 系统约束

系统设计基于以下硬件和运行约束：

- CAN1 与 CAN2 均为经典 CAN，速率 `1 Mbps`；
- CAN1 连接 GM6020 和 VESC，是本地电机总线；
- CAN2 连接主控，只接收本轮的控制和心跳；
- GM6020 使用旧版固件默认电压控制；
- VESC 内部已经完成轮向速度闭环；
- GM6020 编码器只有单圈 `0..8191` 信息；
- 当前机械结构为直驱，减速比 `1.0`；
- 主控目标不是周期性重发，只在目标变化时发送控制帧；
- 主控通过心跳维持链路，不通过重复控制帧维持目标。

## 3. 关键设计问题与决策

| 问题                   | 设计决策                       | 原因与代价                  |
| -------------------- | -------------------------- | ---------------------- |
| 两条 CAN 总线承载不同设备      | CAN1 接收全部，CAN2 精确过滤主控 ID   | 降低主控总线无关帧和错误 ID 干扰     |
| 控制帧只在变化时发送           | 目标持久有效，心跳单独维护链路            | 避免目标未变化时错误地超时失效        |
| 主控重启或链路恢复            | 必须收到新控制帧才恢复运动              | 防止自动执行旧目标，代价是恢复后需要重新下发 |
| 两个执行器可能不同步故障         | 任一执行器离线时整轮失能               | 行为可预测且安全，代价是单点故障会停止整轮  |
| 主控角与舵轮角坐标可能不同        | 应用层显式 `sign/offset` 映射     | 不让协议模块或电机驱动隐含坐标系假设     |
| 舵轮方向存在 180° 等价方案     | AngleOpt 选择更近候选            | 减少舵向旋转，代价是可能反转 ERPM    |
| 大角度阶跃产生机械冲击          | GM6020 目标经过位置斜坡            | 限制速度和加速度，代价是大角度响应变慢    |
| GM6020 与 VESC 控制层级不同 | GM6020 串级 PID，VESC 仅发 ERPM | 复用 VESC 内部速度环，减少分控板计算  |
| 中断和主循环职责冲突           | CAN 中断只解码，TIM6 做全部实时控制     | 控制周期稳定，代价是命令最多延迟 1 ms  |
| 调试输出可能阻塞控制           | UART 中断发送，忙时丢弃本次遥测         | 保证控制实时性，代价是极端情况下遥测不连续  |

## 4. 软件架构

```text
                         CAN2 / 主控
                             │
                             ▼
                       ┌───────────┐
                       │ MasterCan │
                       └─────┬─────┘
                             │ ERPM + 目标角 + 链路状态
                             ▼
                   主控坐标 sign/offset 映射
                             │
                             ▼
                       ┌───────────┐
                       │ AngleOpt  │
                       └─────┬─────┘
                             │ 最终舵向 + ERPM
                 ┌───────────┴───────────┐
                 ▼                       ▼
         ┌─────────────┐          ┌───────────┐
         │ SetpointRamp│          │   VESC    │
         └──────┬──────┘          └─────┬─────┘
                │                       │
                ▼                       │
         ┌─────────────┐                │
         │   GM6020    │                │
         │ 双环位置控制 │                │
         └──────┬──────┘                │
                └──────── CAN1 ─────────┘
```

`main.c` 是顶层组合根，负责：

- 初始化各模块；
- 配置并启动两路 CAN；
- 提供 HAL CAN/TIM/UART 回调；
- 维护整轮安全状态；
- 调度 LED 和串口遥测。

各驱动模块只负责自己的协议、状态和算法，不直接决定整轮是否运行。

## 5. 实时运行模型

| 事件 | 周期 | 所在上下文 | 主要工作 |
|---|---:|---|---|
| GM6020 反馈 | 约 1 ms | CAN1 RX 中断 | 解码角度、RPM、电流、温度 |
| VESC 状态 | 建议 50 Hz | CAN1 RX 中断 | 解码 ERPM、电流、占空比 |
| 主控控制帧 | 目标变化时 | CAN2 RX 中断 | 解码目标并设置新命令标志 |
| 主控心跳 | 建议 80 ms | CAN2 RX 中断 | 刷新主控链路时间戳 |
| 实时控制 | 1 ms | TIM6 中断 | 安全检查、命令应用、PID、斜坡、CAN 发送 |
| LED | 10 ms | 主循环 | 根据在线和使能状态刷新四灯 |
| UART 遥测 | 20 ms | 主循环 + TX 中断 | 50 Hz 输出调试数据 |

控制相关逻辑不在主循环里执行，因此串口和 LED 不会改变 PID 周期。

## 6. 命令数据流

```text
主控 ERPM
  → AngleOpt 原样使用或取反
  → VESC target_erpm

主控角度码
  → 0..360° 主控角度
  → sign/offset 坐标映射
  → AngleOpt 最终舵向
  → SetpointRamp 移动目标
  → GM6020 位置环
```

三个角度层次必须区分：

| 层次 | 含义 |
|---|---|
| 主控目标角 | 主控二维坐标中的运动方向 |
| 映射后目标角 | 转换到舵轮本地坐标后的方向 |
| 最终舵向角 | 在原始方向和反向等价方向中选择的物理目标 |

## 7. 舵向等价选择

同一个底盘运动向量有两种舵轮实现：

```text
A: (target_angle,  target_erpm)
B: (target_angle+180°, -target_erpm)
```

`AngleOpt` 使用最短角距离选择旋转量更小的方案。

例如：

```text
当前 0°，目标 100°，ERPM > 0
A：转 100°
B：转 280°，ERPM < 0
```

选择 B，因为实际只需移动 80°。

候选只在新控制帧到达时计算一次。这样当前角开始变化后，候选结果不会在
1 kHz 循环中频繁翻转。

## 8. GM6020 控制

GM6020 使用位置-速度串级控制：

```text
舵向误差 -> 位置 PID -> 目标 RPM -> 速度 PID -> 电压 raw
```

1.0 参数：

| 参数 | 当前值 |
|---|---:|
| 位置 Kp/Ki/Kd | `20 / 2 / 0.1` |
| 速度 Kp/Ki/Kd | `70 / 50 / 0` |
| 位置积分分离阈值 | `10°` |
| 速度积分分离 | 关闭 |
| 最大目标 RPM | `300` |
| 电压 raw 限幅 | `20000` |
| 反馈超时 | `20 ms` |

位置环启用积分分离，速度环关闭积分分离。速度积分用于克服低速静摩擦；
条件积分抗饱和防止长期饱和后产生大幅过冲。

## 9. 位置斜坡

主控目标角不直接进入位置 PID，而是先经过参考斜坡：

- 最大角速度 `790 °/s`；
- 最大角加速度 `4000 °/s²`。

斜坡计算“按当前最大减速度刚好停在目标处”的速度包络，
再限制参考速度的每周期变化量。小角度形成三角形轨迹，大角度形成
加速-匀速-减速的梯形轨迹。

斜坡只改变 GM6020 目标角。VESC ERPM 按主控和 AngleOpt 结果直接下发。

## 10. 安全状态机

```text
BOOT
  │ 500 ms 自检结束
  ▼
WAIT_COMMAND
  │ 链路正常 + 收到新控制帧 + 两个执行器在线
  ▼
ACTIVE
  │ 任一必要条件失效
  ▼
FAULT
  │ 全部恢复 + 收到新控制帧
  └──────────────▶ ACTIVE
```

安全条件：

- 主控 `link_valid=1`；
- 主控 `control_seen=1`；
- GM6020 在 20 ms 内在线；
- VESC 在 100 ms 内在线。

故障动作：

1. 立即失能 GM6020 和 VESC；
2. 持续发送零电压和零 ERPM；
3. 清除故障期间待处理的控制帧；
4. 保留最后目标值用于故障诊断；
5. 恢复后必须收到新控制帧。

## 11. 通信协议

### 主控 CAN2

| 报文 | ID | 周期 | 负载 |
|---|---|---|---|
| 控制 | `0x100+wheel_id` | 目标变化时 | 大端 ERPM + 大端角度码 |
| 心跳 | `0x110+wheel_id` | 建议 80 ms | 8 字节 |

链路超时为 500 ms。控制帧同时刷新心跳时间戳。

### GM6020 CAN1

| 内容          | 帧          |
| ----------- | ---------- |
| 电压控制 ID 1～4 | `0x1FF`    |
| 电压控制 ID 5～7 | `0x2FF`    |
| 反馈          | `0x204+id` |

### VESC CAN1

| 内容            | 扩展 ID   |
| ------------- | ------- |
| SET_RPM，ID 67 | `0x343` |
| STATUS，ID 67  | `0x943` |

完整字节布局见项目 README 和模块文档。

## 15. 1.0 边界

1.0 有明确的适用范围，不应被理解为通用舵轮框架：

- 只支持一个舵轮、一个 GM6020 和一个 VESC；
- GM6020 只支持单圈绝对角；
- 当前为直驱，减速结构不能直接复用；
- 零位和设备参数是编译期宏，不支持串口在线写入或 Flash 持久化；
- 不向主控发送舵轮状态反馈；
- 主控链路恢复后必须主动下发新控制命令；
- ERPM 不在分控板额外限幅，主控承担速度规划责任；
- PID、斜坡和电压限制依赖当前机械结构和调参结果；
- 串口发送忙时允许丢弃当前遥测帧。
